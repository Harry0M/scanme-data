🔧 Keeping Your Data Up-to-Date

Automatic Updates (GitHub Actions)

The pipeline runs every Monday automatically via GitHub Actions. It:

  1. Downloads CSV files from IARC, EFSA, Prop 65, ECHA
  2. Merges them using CAS Number → E-Number → Name hierarchy
  3. Produces a new regulatory_data.db + version.json
  4. Commits version.json to the repo

Manual Update Steps

  1. Go to your repo → Actions tab → "Update Regulatory Database"
  2. Click "Run workflow" → "Run workflow" (green button)
  3. Wait for it to complete (2-5 minutes)
  4. Download the artifact (regulatory-database.zip) from the completed run
  5. Create a new Release with the .db file attached
  6. Update the url field in version.json to point to the new release

How the Android App Gets Updates

App starts → WorkManager checks version.json (raw.githubusercontent.com)
  → Compares with local version
  → If newer: downloads .db from release URL
  → Validates SHA-256 checksum
  → Replaces local database atomically
  → User never notices (background, silent)

⚠️ Common Errors & Solutions

❌ URL Mismatch / Source Download Failed

Symptom: Pipeline log shows "download failed after 3 attempts" for a source

Cause: The organization changed their download URL

Fix:

  1. Open data_pipeline/build_database.py
  2. Find the SOURCE_URLS dictionary near the top
  3. Google the source name + "download CSV" (e.g., "IARC monographs CSV download")
  4. Update the URL
  5. Commit and push — the next Actions run will use the new URL

❌ CSV Column Names Changed

Symptom: "0 records parsed" for a source even though download succeeded

Cause: The source renamed their CSV columns

Fix:

  1. Download the CSV manually and open in Excel/Sheets
  2. Note the new column names
  3. In build_database.py, find the parser function (e.g., parse_iarc())
  4. Update the column detection logic (the code uses fuzzy matching like "cas" in column_name)
  5. If needed, add the new column name to the matching patterns

❌ Checksum Mismatch in App

Symptom: App keeps retrying database update (check Logcat for "checksum mismatch")

Cause: version.json checksum doesn't match the actual .db file

Fix:

  1. Re-run the pipeline to regenerate both files together
  2. Make sure version.json and regulatory_data.db come from the SAME run
  3. Upload the new .db to a GitHub Release
  4. Update the url in version.json to point to the correct release

❌ GitHub Actions Workflow Not Running

Symptom: No runs appearing in Actions tab

Fix:

  1. Go to repo → Actions tab
  2. If you see "Workflows aren't being run" → click "I understand, enable them"
  3. If the workflow file isn't detected: ensure it's at .github/workflows/update-database.yml
  4. Try triggering manually with "Run workflow" button

❌ New Fields/Attributes Added by Source

Symptom: You discover a new useful column in the source data (e.g., "target_organ")

Fix:

  1. Open the relevant parser function in build_database.py
  2. Add extraction logic for the new column
  3. Map it to the appropriate field (e.g., add to health_categories JSON array)
  4. If it's a completely new data type, add a new column to the schema (see "Adding Sources" tab)
  5. Update Room entity in the Android app to match

➕ Adding New Data Sources or Attributes

Adding a New Data Source

  1. Open data_pipeline/build_database.py
  2. Add the URL to SOURCE_URLS dictionary: 
    SOURCE_URLS = {
    ...
    "NEW_SOURCE": "https://example.com/data.csv",
}
  3. Create a parser function: 
    def parse_new_source(csv_text: str) -> pd.DataFrame:
    # Parse CSV, extract: cas_number, canonical_name, classification, risk_level, health_categories
    # Return DataFrame with standard columns
    ...
  4. Add the parser call in main(): 
    if raw_data.get("NEW_SOURCE"):
    df = parse_new_source(raw_data["NEW_SOURCE"])
    if not df.empty:
        dataframes.append(df)
  5. Run locally to test: python build_database.py
  6. Commit and push

Adding a New Attribute (Column)

Example: adding toxicity_limit (ADI/NOAEL values)

  1. Python script: Add the column to the SQLite schema in build_database()
  2. Android Room entity: Add the field to RegulatoryDataEntity in the database module
  3. Room migration: Increment database version and add migration (or use destructive fallback for dev)
  4. Domain model: Add to RegulatoryClassification in :core
  5. UI: Display in IngredientDetailScreen
