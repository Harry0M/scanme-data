🔬 ScanMe Data Pipeline
How to keep your ingredient database up to date

🗂️ How The System Works (Simple Explanation)

Your app needs a database of ingredients + their health risks. Here's the flow:

You edit 4 CSV files (simple spreadsheets) in the "sources" folder
    ↓
You push to GitHub
    ↓
GitHub Action runs automatically (every Monday)
    ↓
Python script reads your 4 CSV files → builds one .db file
    ↓
You download that .db file → create a GitHub Release
    ↓
Android app checks for new version → downloads it silently

You never touch the .db file directly. You only edit the 4 CSV files. The script does the conversion for you.

✏️ How To Add New Ingredients (Manual Update)

You recommended doing this manually. Here's exactly how:

Step 1: Find an ingredient you want to add

Example: You want to add "Tartrazine" (a food coloring).

Step 2: Look it up on one of the source websites

  • Go to IARC → search for it → note the Group (1, 2A, 2B, 3)
  • Or go to Prop 65 → search → note if it's listed for cancer/reproductive
  • Or go to EFSA → search → note the ADI and hazard
  • Or go to ECHA → search → note hazard class and statements

Step 3: Find the CAS number

Every chemical has a unique CAS number. Find it by Googling: "Tartrazine CAS number" → Result: 1934-21-0

Step 4: Add a new row to the correct CSV file

Open the CSV file in any text editor (Notepad, VS Code) or Excel. Add a new row at the bottom.

For IARC (cancer): Open iarc_classifications.csv and add:
Tartrazine,1934-21-0,3,112,2015
Format: Agent name, CAS number, Group (1/2A/2B/3/4), Volume number, Year
For EFSA (food safety): Open efsa_openfoodtox.csv and add:
Tartrazine,1934-21-0,E102,ADHD link inconclusive,ADI 7.5 mg/kg bw/day,2009
Format: Name, CAS, E-number, Hazard description, Reference point, Year
For Prop 65 (California): Open prop65_chemicals.csv and add:
Tartrazine,1934-21-0,cancer,SQE,01/01/2020
Format: Chemical name, CAS, Type of Toxicity, Listing Mechanism, Date Listed
For ECHA (EU hazards): Open echa_hazards.csv and add:
Tartrazine,1934-21-0,Skin Sens. 1; Eye Irrit. 2,H317 H319 - Skin sensitizer and eye irritant
Format: Name, CAS, Hazard Class, Hazard Statement

Step 5: Push to GitHub

cd c:\Users\palha\scanme\scanme-data
git add .
git commit -m "Added Tartrazine to database"
git push origin main

Step 6: Wait for Monday (or trigger manually)

GitHub Action runs every Monday. Or go to Actions tab → "Run workflow" to trigger now.

Step 7: Create a new Release

  1. After Action completes → download the artifact (regulatory-database.zip)
  2. Go to Releases → Create new release
  3. Tag it with today's date (e.g., v2026-07-30)
  4. Attach the .db file
  5. Publish

The app will pick up the new database automatically within 24 hours.

⚠️ Common Problems & Solutions

Problem: GitHub Action fails
Reason: Usually a typo in a CSV file (missing comma, extra quotes)
Fix: Check the Action log → it tells you which file/line has the error. Fix the CSV and push again.
Problem: I can't find the CAS number for something
Fix: Google "ingredient name CAS number". If it doesn't have one (like "Processed meat"), use 0 as the CAS number. The pipeline handles this.
Problem: An ingredient appears in multiple sources with different names
Example: IARC says "BHT (butylated hydroxytoluene)" but EFSA says "Butylated hydroxytoluene (BHT)"
Fix: This is fine! The pipeline merges them by CAS number. Same CAS = same ingredient. The name difference is just logged as a warning.
Problem: I want to add a brand new data source (not one of the 4)
Fix: Add a new CSV file in the sources/ folder, then update build_database.py to parse it. See the "Adding Sources" section in the Python code.
Problem: App doesn't pick up the new database
Reasons:
  • You forgot to create a GitHub Release (the app downloads from releases, not raw files)
  • The version.json in the repo root still has the old version number
  • The checksum in version.json doesn't match the .db file (they must come from the same pipeline run)
Fix: Re-run pipeline → create release with the new .db → copy version.json to repo root → push
